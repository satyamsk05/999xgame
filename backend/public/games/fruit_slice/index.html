# Comprehensive Bug Fix & Real Game Engine Integration Plan The user requested to analyze the entire application (games, UI/design, server, state management) to identify bugs and replace all fake simulations with a real working game and wallet engine connected to the Node.js backend. ## Findings & Bug Analysis 1. **Backend Server (`backend/server.js`)**: - `/api/wallet/transactions` exists on server, but `ApiService` in Flutter was missing a `getTransactions()` helper. - 7 Up Down HTML5 game was only posting winnings to `/api/games/claim-winnings` without deducting bet amounts from backend `userState` on entry or per-round bet placement. 2. **Flutter API Service (`lib/services/api_service.dart`)**: - `ApiService` was defined but never imported or called anywhere in `lib/main.dart` or any screen. - Missing `getTransactions()` method to fetch transactions from server. 3. **Flutter State Management (`lib/main.dart`)**: - App used static hardcoded local state (`_depositBalance = 800.0`, static `_transactionsList`). - Adding cash, withdrawing, or joining games operated purely in memory without syncing with `server.js`. 4. **HTML5 Game Screen (`lib/screens/html5_game_screen.dart`)**: - Used a hardcoded simulated 30-second countdown timer and local simulated entry fee deduction. - Did not call `ApiService.joinGame(...)` before starting game or update parent wallet state when game completed. 5. **HTML5 Games (`backend/public/games/`)**: - `seven_up_down/index.html`: Bet placement only modified local JS variable `userBalance` without sending bet deduction to server `/api/games/join`. - `fruit_slice/index.html`: Claimed winnings on game over, but entry fee was not deducted from server backend first. --- ## Proposed Changes ### Backend Component (`backend/server.js` & HTML5 Games) #### [MODIFY] [server.js](file:///Users/satyamkumar/Desktop/ingames/backend/server.js) -
